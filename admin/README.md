# پشتیبانی ماهریاب

اپلیکیشن PWA برای تیم پشتیبانی جهت پیگیری تماس با مخاطبان و ثبت نتیجه تماس، بدون نیاز به سرور — داده‌ها مستقیم روی یک ریپازیتوری گیت‌هاب نگهداری می‌شوند.

## ساختار پروژه
```
index.html          صفحه اصلی برنامه
manifest.json        مشخصات نصب PWA
service-worker.js     کش آفلاین (پوسته برنامه + آخرین داده دریافتی)
js/github.js          خواندن/نوشتن فایل‌های JSON روی گیت‌هاب
js/app.js             منطق برنامه، رندر کارت‌ها، چک‌لیست، تب‌ها
icons/                آیکون‌های نصب
data/contacts.json     لیست مخاطبان (اطلاعات ثابت)
data/followups.json    وضعیت پیگیری هر مخاطب (اطلاعات متغیر)
```

دو فایل داده از طریق فیلد `id` (در contacts.json) و `contact_id` (در followups.json) به هم متصل‌اند و شماره‌گذاری از ۱ شروع می‌شود. همین عدد به‌عنوان «شماره کارت» روی هر کارت نمایش داده می‌شود.

## راه‌اندازی (یک‌بار)

1. **ساخت ریپازیتوری**: یک ریپازیتوری جدید در گیت‌هاب بسازید و تمام فایل‌های این پوشه را در آن push کنید.
2. **فعال‌سازی GitHub Pages**: در تنظیمات ریپازیتوری → Pages → Source را روی شاخه `main` و پوشه `/ (root)` قرار دهید. آدرسی مثل `https://username.github.io/repo-name/` ساخته می‌شود.
3. **ساخت توکن دسترسی**: در تنظیمات گیت‌هاب یک **Fine-grained Personal Access Token** بسازید که فقط به همین یک ریپازیتوری محدود باشد و فقط دسترسی `Contents: Read and write` داشته باشد. مدت انقضای کوتاه (مثلاً ۹۰ روز) و تمدید دوره‌ای توصیه می‌شود.
4. **باز کردن سایت روی گوشی پشتیبان** و از منوی مرورگر گزینه «افزودن به صفحه اصلی / نصب برنامه» را بزنید تا به‌صورت PWA نصب شود.
5. داخل برنامه، روی آیکون ⚙️ (تنظیمات) بزنید و نام کاربری گیت‌هاب، نام ریپازیتوری، شاخه، و توکن را وارد کنید. این اطلاعات فقط در حافظه همان گوشی (localStorage) ذخیره می‌شود.
6. برای افزودن مخاطبان واقعی، فایل `data/contacts.json` را ویرایش کنید (مستقیم در گیت‌هاب یا از طریق ابزار دلخواه). هر مخاطب باید `id` یکتا و افزایشی داشته باشد.

## منطق تب‌ها (نحوه دسته‌بندی خودکار کارت‌ها)

| تب | شرط |
|---|---|
| پیگیری‌نشده | هیچ تماسی ثبت نشده، یا تماس اول بی‌پاسخ بوده («جواب نداد ۱») و هنوز آماده تماس مجدد است |
| پیگیری اول | تماس اول برقرار شده و نتیجه‌ای غیر از «تعیین وقت» ثبت شده، و هنوز تماس دوم ثبت نشده |
| تعیین‌وقت‌شده | در پیگیری اول یا دوم، گزینه «تعیین وقت» انتخاب شده باشد (این وضعیت همیشه اولویت دارد) |
| بایگانی | تماس دوم بی‌پاسخ بوده، یا تماس دوم برقرار شده اما نتیجه‌اش «تعیین وقت» نبوده |

نکته: پیش از ثبت هر کارت، اگر پیگیری اول یا دوم تیک خورده باشد ولی نتیجه (یکی از گزینه‌ها) انتخاب نشده باشد، برنامه اجازه ثبت نمی‌دهد — این تضمین می‌کند وضعیت «بایگانی» همیشه بر اساس یک نتیجه مشخص تعیین شود، نه یک تیک خالی.

## نحوه ذخیره تغییرات

هنگام باز شدن برنامه، اطلاعات از آدرس `raw.githubusercontent.com` خوانده می‌شوند (سریع و قابل کش). با زدن دکمه «ثبت» روی هر کارت، برنامه از طریق GitHub Contents API (با توکن ذخیره‌شده) نسخه فعلی `followups.json` را می‌خواند، فقط رکورد همان مخاطب را به‌روزرسانی می‌کند و کامیت جدیدی می‌سازد — این کار احتمال رونویسی تغییرات هم‌زمان چند پشتیبان را کم می‌کند.

اگر ریپازیتوری خصوصی (Private) باشد، تیک «این مخزن خصوصی است» را در تنظیمات بزنید تا خواندن اطلاعات هم از طریق API احراز‌هویت‌شده انجام شود (چون آدرس raw عمومی برای ریپازیتوری خصوصی کار نمی‌کند).

## نکته امنیتی مهم درباره توکن

نگهداری توکن در localStorage گوشی، مشکل «توکن داخل کد عمومی» را حل می‌کند، اما توکن هنوز روی خود گوشی ذخیره است. اگر گوشی پشتیبان گم شود یا قفل نداشته باشد، فرد دیگر می‌تواند از طریق ابزارهای توسعه مرورگر به آن دسترسی پیدا کند. توصیه می‌شود:
- روی هر گوشی از توکنی جداگانه استفاده شود (نه یک توکن مشترک بین همه پشتیبان‌ها) تا در صورت لو رفتن، فقط همان یکی باطل شود.
- قفل صفحه گوشی فعال باشد.
- محدوده توکن فقط به همین ریپازیتوری و فقط خواندن/نوشتن محتوا محدود باشد (نه دسترسی کامل حساب).

## فرضیات طراحی (برای هماهنگی با شما)

چون چند نکته در توضیحات اولیه قابل چند برداشت بود، این فرض‌ها در نسخه فعلی اعمال شده‌اند و به‌راحتی قابل تغییرند:
- «جواب نداد ۱» باعث بایگانی نمی‌شود؛ فرد در تب «پیگیری‌نشده» با یک نشانه «نیاز به تماس مجدد» باقی می‌ماند تا دوباره تماس گرفته شود.
- انتخاب «تعیین وقت» (چه در پیگیری اول، چه دوم) همیشه بر قوانین بایگانی اولویت دارد، دقیقاً مطابق آنچه خواسته بودید.
- یک فیلد اختیاری «یادداشت زمان قرار» اضافه شده که فقط وقتی «تعیین وقت» انتخاب شود ظاهر می‌شود (قابل حذف در صورت عدم نیاز).

اگر هرکدام از این فرض‌ها با نیاز واقعی تیم فرق دارد، به‌راحتی در `js/app.js` (تابع `computeBucket`) قابل تغییر است.
